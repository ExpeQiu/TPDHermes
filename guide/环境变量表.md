# 环境变量表

## 后端

| 变量 | 说明 | 默认 |
|------|------|------|
| `DATABASE_URL` | 异步 SQLAlchemy URL | `sqlite+aiosqlite:///./tphermes.db` |
| `CORS_ALLOWED_ORIGINS` | 逗号分隔 Origin | `http://localhost:3000,http://localhost:8080` |
| `CHROMA_HOST` | 外部 Chroma 根 URL | `http://localhost:8001` |
| `KB_EMBED_ENABLED` | 是否用 Sentence Transformers 生成 `query_embeddings` | `1` |
| `KB_EMBED_ON_UPSERT` | ingest/upsert 是否写入 `embeddings` | `1` |
| `KB_EMBED_MODEL` | 本地 embedding 模型（HuggingFace 名） | `BAAI/bge-small-zh-v1.5` |
| `KB_EMBED_CACHE_DIR` | Embedding/HuggingFace 缓存目录（建议挂载持久卷） | `<项目根>/.cache/huggingface`（容器内建议 `/app/.cache/huggingface`） |
| `KB_EMBED_WARMUP` | 是否在启动时预热 embedding 模型 | `1` |
| `KB_EMBED_WARMUP_BLOCKING` | 是否阻塞启动直到预热结束（首请求不吃冷启动） | `0` |
| `KB_EMBED_WARMUP_TIMEOUT_SEC` | 预热超时秒数；`<=0` 表示不设超时 | `180` |
| `KB_LOCAL_RANK_MAX_DOCS` | 无向量索引时本地重排拉取文档上限 | `500` |
| `HERMES_CHAT_API_URL` | 后端代理到的聊天补全 URL | `http://localhost:8642/v1/chat/completions` |
| `HERMES_CHAT_API_KEY` | 后端代理使用的 API Key；若未显式设置，`./start.sh` 会尝试从 `~/.hermes/.env` 的 `API_SERVER_KEY` 自动映射 | 空 |
| `HERMES_CHAT_MODEL` | 后端代理默认模型名 | `hermes-agent` |
| `FEISHU_APP_ID` | 飞书应用 ID（可选） | 空 |
| `FEISHU_APP_SECRET` | 飞书应用密钥 | 空 |
| `PROJECT_KB_INGEST_ENABLED` | 是否启用项目附件/输出自动写入 `project.{id}.kb` | `1` |
| `PROJECT_UPLOAD_DIR` | 项目附件存储目录 | `backend/data/project_uploads` |
| `PROJECT_ATTACHMENT_MAX_BYTES` | 单附件大小上限（字节） | `33554432` |
| `WORKSHOP_REFINE_FULL_SOURCE` | 工坊优化模式是否仍将来源输出全文注入 `task_input` | 未设（默认走 KB 检索） |
| `WORKSHOP_EXECUTION_MODE` | 工坊执行模式：`agent`（经 Hermes-agent + MCP）或 `direct`（本地直连 skill） | `agent` |
| `WORKSHOP_AGENT_FALLBACK_DIRECT` | Agent 模式未捕获 tool 结果时是否降级直连 skill（开发用） | 未设（关闭） |
| `HERMES_ORCHESTRATION_MODE` | 编排合同注入方式：`prompt`（system 嵌入 JSON）或 `extra` | `prompt` |

### 本地联动说明

- 当前推荐的本地链路是：`hermes-agent` 在 `~/.hermes/.env` 中保存 `API_SERVER_KEY`，`TPDHermes` 通过 `./start.sh` 启动时自动读取该值并映射到 `HERMES_CHAT_API_KEY`。
- 若手动执行 `uvicorn main:app ...` 而不是 `./start.sh`，则需要自行导出 `HERMES_CHAT_API_KEY`；否则 `/api/v1/chat/completions` 可能返回上游鉴权失败。
- 前端直连模式使用的是 `NEXT_PUBLIC_CHAT_API_KEY`，与后端代理模式下的 `HERMES_CHAT_API_KEY` 不是同一条配置链路。

## 前端（`NEXT_PUBLIC_*` 构建期注入）

| 变量 | 说明 | 默认 |
|------|------|------|
| `NEXT_PUBLIC_API_URL` | 后端根 URL（不含 `/api/v1`） | `http://localhost:8000` |
| `NEXT_PUBLIC_USE_MOCK_KB` | 为 `true` 时知识库失败回退演示数据 | 未设则关闭 |
| `NEXT_PUBLIC_CHAT_API_URL` | 可选，覆盖前端默认聊天入口；未设时走 `/api/v1/chat/completions` | 未设 |
| `NEXT_PUBLIC_CHAT_API_KEY` | 仅当前端直连外部聊天服务时使用 | 空 |
| `NEXT_PUBLIC_FEEDBACK_API_URL` | 若存在则提交评价到该绝对地址 | 空（仅本地） |

## Docker Compose

- `backend`：`DATABASE_URL` 可挂载卷内 SQLite。
- `backend`：若需要代理本机 `Hermes-agent`，请显式注入 `HERMES_CHAT_API_KEY`；Docker Compose 不会自动读取宿主机 `~/.hermes/.env`。
- `frontend`：`NEXT_PUBLIC_API_URL` 在**浏览器**访问时应指向可访问的后端主机（开发机常用 `http://localhost:8000`）。
