缺失是递进关系：**没有反馈信号 → 无法主动学习 → 知识积累无据可依**。顺着这个逻辑链深入：

---

## 第一层：反馈信号 — 最基础的缺失

### 现状问题

Hermes 的消息流是**单向的**：用户发消息 → Agent 回复 → 结束。没有机制捕获"这个回复好不好"。

### 现有可利用的能力

**Feishu/chatui 消息 reactions** 是最自然的反馈入口，但 gateway 目前没有捕获 reactions。

**Cron 定时触发** 可以在对话结束后主动询问：

```
每条回复后 → Cron 探测该消息是否有 👍/👎 reaction
无 reaction → 24小时后发确认消息："上文采纳了吗？"
用户回复"采纳"或"重写" → 触发 learning 流程
```

**Skill 层面的反馈捕获**（当前可落地）：

```
用户每次纠正 Agent 时 → 自动写入 memory
格式："{日期} {场景} {用户纠正内容} {原Agent行为}"
```

这样同一错误不会被重复犯两次。

---

## 第二层：主动学习触发 — Curator 可以改造

Hermes 内置的 Curator 本职是**技能生命周期管理**（归档闲置技能），但它的触发机制可以扩展为**学习机会探测**：

```
 Curator 检查项：
  ├─ 使用率 < 3次的 Skill → 标记为"未验证"，提示用户是否有效
  ├─ 连续 3次 同一类任务被重新描述 → 说明 Skill 模板不够通用，需更新
  ├─ memory 中某类纠正出现 2次以上 → 提示用户"是否创建/更新 Skill"
  └─ KB 查询返回 null 的术语 → 提示用户补充知识库
```

**问题在于**：Curator 是后台静默运行的，用户感知不到它在"学习"。它应该有一个**可见的输出**，比如每周给用户一个「本周学习报告」：

```
本周学习摘要：
✅ 已学会：竞品分析报告的标准结构（技能更新1次）
✅ 已记住：技术口径已统一为「雷神智擎Hi·X」
⚠️ 待确认：吉利EM-i与雷神智擎Hi·X的关系是什么？
📝 新增知识库条目：千里浩瀚智驾系统技术参数
```

---

## 第三层：私有知识积累 — 需要新的存储结构

当前 KB 的问题是**只存结果，不存学习过程**。真正的知识体系需要三层：

```
第1层：原始语料  → KB（吉利官网内容、技术文档）
第2层：经验知识  → Skill（经过验证的工作流程、写作模板）
第3层：判断标准  → Memory（用户的偏好、质量判断准则）
```

目前 TPDHermes 的 KB collection 是扁平的四类：

- `geely_tech` — 吉利技术库
    
- `auto_company_strategy` — 竞品策略
    
- `speeches` — 发言稿
    
- `remote_debug` — 技术调试
    

**缺失的是第五层——「TPD 经验库」**：

```
collection: tpd_experience
结构：
  - 场景标签（竞品分析/发言稿/技术科普/产品对比...）
  - 用户反馈（采纳/不采纳/修改后采纳）
  - 迭代记录（同一任务每次生成的内容差异）
  - 有效期（哪些判断标准会随时间失效）
```

---

## 三个缺失的系统性解法

```
用户互动
    │
    ├─► [反馈捕获层]
    │      Feishu reactions（需开发） 或 Cron 确认询问
    │      → 写入 memory：「{场景} {日期} {反馈}」
    │
    ├─► [学习决策层]
    │      Curator 扩展：检测 feedback 聚类
    │      → 发现模式：「竞品分析框架已被2次纠正」
    │      → 触发 Skill 更新 或 KB 补充
    │
    └─► [知识输出层]
             Skill（工作流程）
             KB（事实型知识，published=true）
             Memory（判断标准 + 用户偏好）
```

---

## 最关键的卡点

三个缺失中，**反馈信号是核心瓶颈**：

- 没有它，Curator 无法判断什么是"好的学习"
    
- 没有它，知识积累无法区分"存进去了"和"存对了"
    
- 没有它，主动学习触发只是定时发提醒，而非真正优化
    

**建议优先实现**：在 Feishu / chatUI的gateway 加一个轻量级的 reaction 监听器，把 👍/👎 或「采纳/不采纳」的反应写入 memory，格式统一为：

```
[feedback] {日期} {session_id} {场景标签} {采纳程度：full/partial/reject} {简要原因}
```

这条记录会同时成为 Curator 的学习原料和 Skill/KB 更新的触发依据。
