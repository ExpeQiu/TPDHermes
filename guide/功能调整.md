**一、产品定位重构**

- `场景编排`：围绕“场景”定义执行合同，配置技能、知识范围、输出模板与规则。
- `结果工坊`：围绕“项目”执行场景，生成结果、优化结果、沉淀结果。
- `Project` 是业务承载体。

**三、数据与接口方案**

下面是正式的数据模型设计。

---

**3.1 核心实体**

建议核心实体拆为 6 类：

- `projects`
- `scenario_profiles`
- `project_scenarios`
- `templates`
- `outputs`
- `orchestration_runs`

其中：

- `projects`：项目主实体
- `scenario_profiles`：场景定义
- `project_scenarios`：项目与场景绑定关系
- `templates`：输出模板
- `outputs`：实际输出物
- `orchestration_runs`：一次执行过程日志

---

**3.2 `projects`**

用途：
- 业务容器
- 承载输出物
- 绑定可用场景

建议字段：

```sql
projects
- id TEXT PK
- name TEXT NOT NULL
- description TEXT NULL
- background TEXT NULL
- audience TEXT NULL
- deadline TEXT NULL
- constraints_json TEXT NULL
- status TEXT NOT NULL
- default_scenario_id TEXT NULL
- created_at TEXT NOT NULL
- updated_at TEXT NOT NULL
```

补充说明：
- `constraints_json` 用于项目级限制，如语气、篇幅、术语要求
- `default_scenario_id` 用于默认结果工坊场景

---

**3.3 `scenario_profiles`**

用途：
- 表示一个完整的“场景编排定义”

建议字段：

```sql
scenario_profiles
- id TEXT PK
- code TEXT UNIQUE NOT NULL
- name TEXT NOT NULL
- description TEXT NULL
- category TEXT NULL
- goal TEXT NULL
- conversation_mode TEXT NOT NULL
- domain_json TEXT NOT NULL
- knowledge_policy_json TEXT NOT NULL
- skills_policy_json TEXT NOT NULL
- output_policy_json TEXT NOT NULL
- version TEXT NOT NULL
- status TEXT NOT NULL
- created_by TEXT NULL
- created_at TEXT NOT NULL
- updated_at TEXT NOT NULL
```

JSON 字段建议：

`domain_json`
```json
{
  "technical_scope": ["智能座舱", "车载语音"],
  "business_scope": ["方案说明"],
  "excluded_topics": ["价格承诺"],
  "terminology_policy": "tpd_standard"
}
```

`knowledge_policy_json`
```json
{
  "mode": "restricted",
  "collections": ["tpd_docs", "product_specs"],
  "project_bound": true,
  "top_k": 5,
  "fallback_policy": "cache_allowed"
}
```

`skills_policy_json`
```json
{
  "mode": "allowed_list",
  "allowed": ["a4_skill", "speech_skill"],
  "preferred": ["a4_skill"],
  "forbidden": [],
  "allow_agent_free_choice": false
}
```

`output_policy_json`
```json
{
  "template_id": "tpl_solution_v1",
  "format": "markdown",
  "must_follow_template": true,
  "required_sections": ["背景", "目标", "方案设计", "优势", "风险"]
}
```

---

**3.4 `project_scenarios`**

用途：
- 记录项目与场景的绑定关系
- 支持一个项目绑定多个场景

建议字段：

```sql
project_scenarios
- id TEXT PK
- project_id TEXT NOT NULL
- scenario_id TEXT NOT NULL
- scenario_version TEXT NOT NULL
- is_default INTEGER NOT NULL DEFAULT 0
- enabled INTEGER NOT NULL DEFAULT 1
- created_at TEXT NOT NULL
- updated_at TEXT NOT NULL
```

说明：
- 一个项目可以绑定多个场景
- 一个场景可以被多个项目复用
- 默认结果工坊优先加载 `is_default = 1` 的场景

---

**3.5 `templates`**

用途：
- 正式输出模板资产

建议字段：

```sql
templates
- id TEXT PK
- name TEXT NOT NULL
- description TEXT NULL
- category TEXT NULL
- format TEXT NOT NULL
- schema_json TEXT NOT NULL
- version TEXT NOT NULL
- status TEXT NOT NULL
- created_at TEXT NOT NULL
- updated_at TEXT NOT NULL
```

`schema_json` 示例：

```json
{
  "required_sections": ["背景", "目标", "方案设计", "优势", "风险"],
  "optional_sections": ["实施建议", "后续规划"],
  "validation_rules": {
    "must_have_headings": true,
    "must_cite_sources": true
  }
}
```

---

**3.6 `outputs`**

用途：
- 表示某个项目在某个场景下的一次正式输出物

建议字段：

```sql
outputs
- id TEXT PK
- project_id TEXT NOT NULL
- scenario_id TEXT NOT NULL
- run_id TEXT NULL
- template_id TEXT NULL
- title TEXT NULL
- summary TEXT NULL
- content TEXT NOT NULL
- content_format TEXT NOT NULL
- status TEXT NOT NULL
- version INTEGER NOT NULL DEFAULT 1

- metadata_json TEXT NULL
- created_at TEXT NOT NULL
- updated_at TEXT NOT NULL
```

说明：
- `status` 可取 `draft / completed / approved / archived`
- `metadata_json` 可记录 used_skills、used_collections、validation

---

**3.7 `orchestration_runs`**

用途：
- 记录一次任务执行过程
- 用于可追踪、可调试、可回看

建议字段：

```sql
orchestration_runs
- id TEXT PK
- project_id TEXT NULL
- scenario_id TEXT NULL
- entrypoint TEXT NOT NULL
- status TEXT NOT NULL
- request_json TEXT NOT NULL
- snapshot_json TEXT NULL
- response_metadata_json TEXT NULL
- validation_json TEXT NULL
- assistant_content TEXT NULL
- error_message TEXT NULL
- duration_ms INTEGER NULL
- created_at TEXT NOT NULL
- updated_at TEXT NOT NULL
```

说明：
- `entrypoint`：`chat / workshop / project / quick_create`
- `snapshot_json`：执行时的编排快照
- `response_metadata_json`：使用了哪些知识库、技能、模板

---

**3.8 关系说明**

关系建议为：

- `Project 1 - N Output`
- `Project N - N Scenario` 通过 `project_scenarios`
- `Scenario 1 - N Output`
- `Scenario 1 - N Run`
- `Run 1 - 0..1 Output`
- `Template 1 - N Scenario`
- `Template 1 - N Output`

**五、前后端职责划分**

**前端负责**
- 选择项目
- 选择场景
- 收集本次输入
- 展示编排摘要
- 展示生成结果、输出历史、运行记录

**后端负责**
- 根据 `project + scenario + overrides` 组装 `OrchestrationPayload`
- 做项目、场景、模板、技能合法性校验
- 决定是否走 workshop 直连 skill 或 Hermes-agent
- 回写 `runs` 与 `outputs`

**Hermes-agent 负责**
- 遵循场景编排合同
- 调用技能与知识工具
- 按模板生成结果
- 返回元数据与正文

**七、最终定义**

建议你在产品文档里直接写成下面这段：

- `场景编排`：用于定义某类业务场景的执行规则，包括技能策略、知识范围、输出模板和结构约束，是可复用的生成合同。
- `结果工坊`：用于在具体项目下选择场景并执行生成，形成输出物、运行记录和结果版本，是面向交付的生产入口。
